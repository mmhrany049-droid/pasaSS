# راه‌اندازی سایت SS

سه راه، از ساده به کامل. در هر سه، داده‌های هر دانش‌آموز فقط روی دستگاه خودش می‌ماند؛ فقط فایل‌هایی که خودش می‌فرستد (با اجازه‌هایی که خودش داده) به مرکز می‌رسد.

## ۱) بدون سرور (همین الان)
`npm install && npm run build` ← پوشه `dist/` را روی فلش، لپ‌تاپ یا هر هاست ساده کپی کن.
- اپ دانش‌آموز: `index.html`
- پروژه مرکز: `hub.html`
تبادل با فایل: دانش‌آموز «ساخت فایل برای مرکز» (`.sspack`) ← مرکز همه را وارد می‌کند ← «ساخت و دانلود» (`.ssbulletin`) ← دانش‌آموزان واردش می‌کنند.

## ۲) هاست استاتیک (GitHub Pages / Netlify / nginx)
- GitHub Pages: فایل `.github/workflows/deploy-pages.yml` آماده است؛ مخزن را push کن و در Settings → Pages منبع را «GitHub Actions» بگذار.
- Netlify: `netlify.toml` آماده است.
- nginx: `deploy/nginx.conf`.
تبادل هنوز با فایل است.

## ۳) سرور کامل (ارسال و دریافت آنلاین)
```
docker compose -f deploy/docker-compose.yml up -d --build
```
یا بدون داکر:
```
npm run build
HUB_ADMIN_TOKEN=یک-رمز-طولانی PORT=8080 node server/hub-server.mjs
```
بعد:
- در اپ دانش‌آموز: تنظیمات ← «آدرس سرور مرکز» (مثلاً `https://ss.example.ir`). دکمه‌های «ارسال آنلاین / دریافت آنلاین» ظاهر می‌شوند.
- در پروژه مرکز: میز کار ← آدرس سرور + رمز مدیر ← «گرفتن فایل‌ها» و «انتشار روی سرور».
- داده سرور در `DATA_DIR` (پیش‌فرض `./data`) است: از آن پشتیبان بگیر.
- حتماً پشت HTTPS اجرا کن (مثلاً Caddy یا nginx + certbot).

### API
| مسیر | دسترسی | کار |
|---|---|---|
| `GET /api/health` | عمومی | سلامت |
| `POST /api/packs` | عمومی (محدودیت نرخ، کنترل صحت SHA-256) | ارسال بسته دانش‌آموز |
| `GET /api/bulletin/latest` | عمومی | آخرین اطلاع‌رسانی |
| `GET /api/packs`, `GET /api/packs/:id` | مدیر | فهرست و دریافت بسته‌ها |
| `POST /api/bulletin` | مدیر | انتشار اطلاع‌رسانی |

مرحله بعد (وقتی کاربر زیاد شد): ورود با حساب کاربری و پایگاه داده — قرارداد کامل در `docs/handoff/api/hub_sync.openapi.yaml` آماده است و `src/sync/transport.js` فقط باید آدرس‌ها را عوض کند.
